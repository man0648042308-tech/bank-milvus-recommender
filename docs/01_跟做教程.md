# Day32复现指南：先跑通，再理解，再复现

## 今天必须形成的模型

你现在只需要牢牢记住三个对象：

1. **向量**：一串数字，用来表示某个内容的特征。
2. **Collection**：Milvus中存放同类数据的集合，类似关系数据库中的表。
3. **Search**：拿查询向量去找最相似的数据。

先不要背全部API。今天的目标是能口述并复现这条链路：

```text
连接 → 建Collection → 插入 → 查询向量 → 过滤 → Top-K结果
```

## 第0步：确认服务，而不是直接写代码

Windows PowerShell运行：

```powershell
Test-NetConnection 192.168.220.77 -Port 19530
```

逐词解释：

- `Test-NetConnection`：测试网络连接。
- `192.168.220.77`：你的虚拟机IP。
- `-Port`：指定要测试的端口参数。
- `19530`：Milvus默认客户端端口。

只有看到`TcpTestSucceeded : True`，才进入下一步。否则先解决服务，不要靠改Python碰运气。

这一步故意不连接数据库，验证三个确定性规则：

## 第3步：运行完整项目

```powershell
uv run python -m bank_milvus.main
```

程序执行顺序：

1. `main()`调用`connect_client()`。
2. `prepare_demo_data()`创建Collection并插入五个产品。
3. `recommend_products()`把需求变成查询向量。
4. `build_business_filter()`生成风险与金额条件。
5. `client.search()`在合格产品中找Top-K。
6. `main()`用`for`循环打印结果。
7. `finally`保证客户端被关闭。

## Traceback阅读顺序

1. 看最后一行：错误类型和直接原因。
2. 从下往上找第一个属于本项目的文件位置。
3. 判断属于哪一层：Python、依赖、网络、Milvus Schema还是数据。
4. 只改变一个原因，再完整回归。

常见例子：

- `Connection refused`：19530没监听，先查虚拟机服务。
- `ModuleNotFoundError`：没在项目环境运行或依赖没同步。
- `DataNotMatchException`：数据键名、字段类型或向量维度不符合Schema。
- `MilvusException`：继续阅读异常中的code和message，不要只看大类名称。
