# Day32学习总结：向量数据库与Milvus

## 一、今天完成了什么

今天使用Windows上的VS Code编写PyMilvus客户端代码，连接VMware Ubuntu虚拟机中运行的Milvus 2.6 Standalone，完成了银行产品Collection创建、产品插入、标量查询、向量相似度搜索和风险/起投金额过滤。

最终业务流程是：把用户需求转换为查询向量，先使用风险等级和可投资金额过滤不合格产品，再使用COSINE相似度返回最匹配的Top-K产品。

## 二、为什么需要向量数据库

关系数据库擅长精确条件，例如“风险等级小于等于2”。但是用户可能输入“我想要本金相对安全、收益稳定的产品”，这句话和产品描述未必使用完全相同的关键词。向量可以表示内容特征，使系统能够根据相似程度检索。

向量数据库负责高效保存向量、构建索引并执行最近邻检索。它通常不会完全替代MySQL或PostgreSQL，而是与关系数据库配合：关系数据库保存交易等强一致数据，向量数据库负责语义检索。

## 三、Milvus核心概念

- Database：数据库级命名空间。
- Collection：一类实体的集合，类似表。
- Schema：Collection字段合同。
- Entity：一条数据，例如一个银行产品。
- Scalar Field：名称、风险、金额等普通字段。
- Vector Field：保存向量的字段。
- Index：加速向量搜索的数据结构。
- Metric：衡量向量相似或距离的方式，本项目使用COSINE。
- Top-K：返回相似度最高的K条结果。
- Filter：在向量搜索前使用普通字段限制候选数据。

## 四、本项目的关键设计

1. 只允许程序删除`day32_`开头的练习Collection，避免误删其他数据。
2. 使用独立配置文件管理虚拟机地址，避免到处硬编码老师机器的IP。
3. 将连接、数据、向量化、检索、入口和测试拆开，便于定位错误。
4. 先执行风险和金额过滤，再做相似度排序，避免向不合格用户推荐高风险产品。
5. 使用独立验收脚本验证真实Milvus，而不是只根据输出判断成功。

## 五、我目前能够解释的执行路径

`main()`先连接Milvus，再创建Collection和插入五个产品。用户文本经过`build_query_vector()`转换为四维查询向量；风险与金额经过`build_business_filter()`变成Milvus过滤表达式；`client.search()`对过滤后的产品执行COSINE搜索；最后循环输出推荐产品。
